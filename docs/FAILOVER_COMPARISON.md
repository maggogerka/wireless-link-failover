# Сравнение контролируемых серий переключения

> Этот документ сравнивает исходные серии с различавшимися настройками.
> Последующее сравнение при одинаковой конфигурации находится в
> [`STANDARDIZED_FAILOVER_COMPARISON.md`](STANDARDIZED_FAILOVER_COMPARISON.md).

## Назначение анализа

Сравниваются две завершённые серии автоматического переключения
`ESP-NOW → UDP → ESP-NOW`:

- ESP8266 ↔ ESP32, пять повторов 8 ноября 2026 года;
- ESP8266 ↔ ESP32-S3, пять повторов 7 ноября 2026 года.

В обоих случаях расстояние составляло 100 см, использовалась точка доступа
`Lab-2G` в диапазоне 2,4 ГГц на канале 6, а отказ создавался управляемым
подавлением прикладных ESP-NOW ACK на приёмнике.

Исходные сводки:

- `experiments/results/failover_8266_32_controlled_5x_20261108_summary.json`;
- `experiments/results/failover_8266_s3_controlled_5x_20261107_summary.json`.

Воспроизводимый анализ выполняется командой:

```powershell
python experiments/analyze_failover_comparison.py
```

Она создаёт машинную сводку
`experiments/results/failover_comparison_20261109.json` и рисунок
`experiments/figures/failover_comparison_20261109.svg`.

## Наблюдавшиеся результаты

| Показатель | ESP8266 ↔ ESP32 | ESP8266 ↔ ESP32-S3 |
|---|---:|---:|
| Успешный переход на UDP | 5/5 | 5/5 |
| Успешный возврат на ESP-NOW | 5/5 | 5/5 |
| ESP-NOW ACK до отказа | 100,000 % | 99,617 % |
| Переход на UDP, среднее | 7,689 с | 8,750 с |
| Переход на UDP, стандартное отклонение | 0,919 с | 1,373 с |
| Возврат на ESP-NOW, среднее | 15,214 с | 30,534 с |
| Возврат на ESP-NOW, медиана | 14,472 с | 15,311 с |
| Возврат на ESP-NOW, стандартное отклонение | 1,732 с | 21,011 с |
| Прикладные ACK резервного UDP | 90,226 % | 92,093 % |
| Время в UDP, среднее | 25,013 с | 43,009 с |

Обе реализации выполнили автоматический переход и возврат во всех пяти
повторах. Время обнаружения отказа было одного порядка и соответствовало
решению по двум последовательным окнам длительностью 5 секунд.

Среднее время восстановления серии с ESP32-S3 увеличили два опыта с
результатами 55,348 и 51,664 секунды. Поэтому среднее отличается примерно
вдвое, а медианы двух серий близки: 14,472 и 15,311 секунды. Это важнее для
интерпретации, чем одно сравнение средних значений.

Разница успешности UDP составила 1,867 процентного пункта в пользу серии с
ESP32-S3. При пяти повторах и различавшейся длительности резервного режима
этого недостаточно для вывода о преимуществе одной платы.

## Почему это ещё не чистое сравнение микроконтроллеров

| Параметр | Серия с ESP32 | Серия с ESP32-S3 |
|---|---:|---:|
| Период основного probe | 470 мс | 500 мс |
| Порог восстановления | 80 % | 90 % |
| Сдвиг recovery probe | 235 мс | 250 мс |
| Период recovery probe | 940 мс | в сводке не зафиксирован |
| Защитный интервал между радиослотами | 470 мс | в сводке не зафиксирован |
| Стабилизационные окна | 3 | в сводке не зафиксированы |
| Энергосбережение Wi-Fi | явно отключено | явно не контролировалось |

Следовательно, сокращение и стабилизация времени возврата в новой серии могли
быть вызваны изменением порога, новым планировщиком радиослотов и отключением
энергосбережения Wi-Fi, а не заменой ESP32-S3 на ESP32. Имеющееся сравнение
следует называть **описательным сравнением двух версий алгоритма и
экспериментальной конфигурации**, а не доказательством превосходства одного
микроконтроллера.

Корректная формулировка для статьи:

> В двух контролируемых сериях по пять повторов автоматический переход на
> резервный UDP и возврат на ESP-NOW состоялись во всех опытах. После
> изменения планировщика восстановительных проверок, снижения порога возврата
> до 80 % и явного отключения энергосбережения Wi-Fi разброс времени возврата
> уменьшился. Для отделения влияния алгоритма от влияния аппаратной платформы
> требуется повторная серия ESP32-S3 с идентичными параметрами.

## Следующий стандартизированный эксперимент

Минимальный следующий этап — повторить пять опытов ESP8266 ↔ ESP32-S3 с той
же текущей прошивкой и тем же порядком направлений `S3, 8266, 8266, S3, S3`,
который использовался в первой серии. Во всех повторах должны быть одинаковы:

- период probe 470 мс;
- окно 5000 мс;
- порог перехода по потерям 30 %;
- порог восстановления 80 %;
- два плохих и три хороших окна;
- recovery probe каждые 940 мс с защитным интервалом 470 мс;
- три стабилизационных окна;
- `wifi_power_save: false` на обеих платах;
- расстояние 100 см, канал 6 и неизменное размещение антенн.

Для отдельного статистического вывода о направлении связи предпочтительны
пять повторов каждого направления для каждой пары, то есть 20 опытов в общей
сложности. Порядок направлений следует чередовать или рандомизировать, чтобы
дрейф радиоканала во времени не совпадал только с одной платой.

## Граница вывода

Испытание проверяет реакцию автомата на подавление прикладных ACK. Оно не
имитирует полный отказ питания узла, физическое экранирование, увеличение
дальности, внешнюю радиопомеху и не измеряет энергопотребление. Эти факторы
нужно исследовать отдельными сериями.
