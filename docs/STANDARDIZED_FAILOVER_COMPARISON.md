# Стандартизированное сравнение ESP32 и ESP32-S3

## Главный результат

После выравнивания настроек автомата и отключения энергосбережения Wi-Fi обе
пары выполнили автоматический переход `ESP-NOW → UDP → ESP-NOW` во всех пяти
циклах. Среднее время возврата практически совпало:

- ESP8266 ↔ ESP32: 15,214 с;
- ESP8266 ↔ ESP32-S3: 15,229 с;
- наблюдавшаяся разница: 0,015 с.

Таким образом, длинные возвраты ESP32-S3 продолжительностью 51–55 секунд из
первой серии не повторились при стандартизированном алгоритме.

## Общие настройки

- расстояние 100 см;
- точка доступа `Lab-2G`, 2,4 ГГц, канал 6;
- период probe 470 мс;
- окно 5000 мс;
- переход при потерях ACK не менее 30 % в двух окнах подряд;
- возврат при успешности ESP-NOW не менее 80 % в трёх окнах подряд;
- recovery probe каждые 940 мс;
- защитный интервал радиослотов 470 мс;
- три стабилизационных окна;
- `wifi_power_save: false` на обоих узлах;
- управляемое подавление прикладного ESP-NOW ACK на приёмнике.

Машинная сводка сравнения находится в
`experiments/results/failover_comparison_standardized_20261109.json`, рисунок
для статьи — в
`experiments/figures/failover_comparison_standardized_20261109.svg`.

## Результаты

| Показатель | ESP8266 ↔ ESP32 | ESP8266 ↔ ESP32-S3 | Разница S3 − ESP32 |
|---|---:|---:|---:|
| Успешный переход на UDP | 5/5 | 5/5 | 0 |
| Успешный возврат на ESP-NOW | 5/5 | 5/5 | 0 |
| Переход на UDP, среднее | 7,689 с | 8,284 с | +0,595 с |
| Переход на UDP, медиана | 8,077 с | 8,405 с | +0,328 с |
| Переход на UDP, стандартное отклонение | 0,919 с | 1,294 с | +0,375 с |
| Возврат на ESP-NOW, среднее | 15,214 с | 15,229 с | +0,015 с |
| Возврат на ESP-NOW, медиана | 14,472 с | 14,488 с | +0,016 с |
| Возврат на ESP-NOW, стандартное отклонение | 1,732 с | 1,539 с | −0,193 с |
| Максимальное время возврата | 18,278 с | 17,448 с | −0,830 с |
| ESP-NOW ACK до отказа | 308/308 | 193/193 | обе серии 100 % |
| ACK резервного UDP | 120/133 | 129/133 | +6,766 п. п. для S3 |
| Время в UDP, среднее | 25,013 с | 24,996 с | −0,017 с |

Разница среднего времени перехода 0,595 секунды меньше одного окна и зависит
от фазы включения отказа внутри пятиисекундного окна. При пяти повторах её
нельзя интерпретировать как доказанное аппаратное различие.

Разница среднего времени возврата 15 мс пренебрежимо мала относительно окна
5000 мс. Наблюдение согласуется с тем, что время возврата задаётся прежде всего
тремя последовательными окнами алгоритма, когда планировщик recovery probe и
режим энергосбережения одинаковы.

Успешность UDP в серии S3 была выше на 6,766 процентного пункта, однако вывод
основан только на 133 probe в каждой серии и единственной локальной сети. Для
вывода о транспортной надёжности нужны отдельные повторные UDP-серии с
рандомизацией порядка направлений.

## Сопоставление с первой серией S3

| Показатель S3 | Первая конфигурация | Стандартизированная конфигурация |
|---|---:|---:|
| Среднее время возврата | 30,534 с | 15,229 с |
| Медиана возврата | 15,311 с | 14,488 с |
| Стандартное отклонение | 21,011 с | 1,539 с |
| Максимум | 55,348 с | 17,448 с |

Среднее время уменьшилось примерно на 50 %, а стандартное отклонение — более
чем на 92 %. При этом нельзя определить вклад каждого изменения отдельно,
поскольку одновременно были изменены порог возврата, планировщик recovery
probe и режим энергосбережения Wi-Fi. Корректный вывод относится ко всей
конфигурации алгоритма, а не к одному параметру.

## Зафиксированное отклонение методики

В новой серии S3 подавление ACK включалось через 16,284–26,429 секунды после
подготовки вместо запланированных 30 секунд. До каждого отказа завершились все
три стабилизационных окна со 100 % ACK, но число дополнительных контрольных
окон составило от нуля до двух.

Поэтому:

- времена перехода после включения fault и возврата после его снятия можно
  использовать для инженерного сравнения одинаково настроенного автомата;
- суммарное число baseline probe нельзя сравнивать как результат одинаковой
  длительности наблюдения;
- серию нельзя называть полностью соответствующей заранее записанному
  30-секундному интервалу.

В GUI добавлена блокировка кнопки `ACK ВЫКЛ.` до истечения 30 секунд после
подготовки отправителя. Следующая серия автоматически исключит такое
отклонение.

## Формулировка для статьи

> При одинаковых параметрах автомата и отключённом энергосбережении Wi-Fi обе
> аппаратные пары выполнили переход на резервный UDP и возврат на ESP-NOW в
> пяти из пяти контролируемых циклов. Среднее время восстановления составило
> 15,214 с для пары ESP8266–ESP32 и 15,229 с для пары ESP8266–ESP32-S3.
> Длинные интервалы восстановления ESP32-S3, наблюдавшиеся в предварительной
> конфигурации, в стандартизированной серии не повторились. Это указывает на
> существенное влияние параметров планировщика и режима энергосбережения, но
> из-за малого числа повторов не является доказательством отсутствия любых
> аппаратных различий.

## Ограничения

Пять циклов на пару и распределение направлений 3/2 достаточны для демонстрации
работы алгоритма, но недостаточны для отдельного вывода о направленной
асимметрии. Также эксперимент не исследует полный отказ питания, физическое
экранирование, дальность, внешнюю помеху и энергопотребление.
